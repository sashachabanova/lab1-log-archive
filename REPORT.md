# Отчёт по лабораторной работе №1

## Цель работы

Автоматизация контроля размера папки и переноса наиболее старых файлов в архив с последующим удалением их оригиналов. Проверка корректности алгоритма автоматическими тестами в GNU/Linux и Windows.

## Реализация

Проект содержит два Bash-скрипта: `log_archive.sh` выполняет архивирование, а `test_log_archive.sh` формирует данные и проверяет результат. Для Windows подготовлены `.bat`-файлы запуска и реализация на Windows PowerShell в соседних `.ps1`.

Основной скрипт принимает путь к папке, порог заполнения, путь к backup и необязательную расчётную ёмкость в МиБ. По умолчанию порог равен 70%, backup располагается рядом с источником, ёмкость берётся у файловой системы или диска.

## Модель заполнения

Обычный каталог не имеет собственной предельной ёмкости. Для расчёта принята формула:

`U = 100 × S / C`,

где S — сумма логических длин обычных файлов в каталоге и подпапках; C — общая ёмкость файловой системы либо явно переданная логическая ёмкость.

В GNU/Linux значение по умолчанию получается через `df -Pk`, в Windows — через `DriveInfo.TotalSize`. Заданная аргументом ёмкость используется в вычислениях и не является ограничением, установленным в ОС. Занятое место остальных каталогов диска в числитель не включается. Ссылки и каталоги не учитываются; жёсткие ссылки считаются по файловым именам.

Архивирование запускается при условии `100 × S > X × C`. Сравнение выполняется без округления. При равенстве порогу файлы остаются на месте.

## Алгоритм

1. Проверка аргументов, зависимостей и расположения backup.
2. Создание блокировки `.lab1.lock` и временной рабочей папки.
3. Рекурсивный поиск обычных файлов без переходов по ссылкам.
4. Сортировка по времени последней модификации от старых к новым.
5. Подсчёт исходного размера и сравнение с порогом.
6. Последовательный выбор старых файлов до достижения допустимого остатка.
7. Создание архива с относительными путями.
8. Проверка архива относительно оригиналов.
9. Публикация проверенного архива в backup и удаление выбранных оригиналов.
10. Вывод результата и очистка временных данных и блокировки.

В Bash список файлов разделяется NUL-символами, что сохраняет имена с пробелами и переводами строк. Для проверки архива используется `tar --compare`. В Windows архив распаковывается во временную папку, после чего содержимое сравнивается по SHA-256.

## Выбор числа файлов

Для файлов, упорядоченных по mtime, после выбора первых n элементов остаток равен:

`R(n) = S − size(f1) − … − size(fn)`.

Выбор останавливается при первом выполнении `100 × R(n) ≤ X × C`. Получается минимальный префикс списка самых старых файлов, достаточный для достижения порога. Минимальность относится к выбору по возрасту, а не к произвольному набору файлов.

При совпадении mtime взаимный порядок одинаково старых файлов может различаться между платформами.

## Сжатие

По умолчанию создаётся `.tar.gz`. При `LAB1_MAX_COMPRESSION=1` создаётся `.tar.lzma`.

В Bash LZMA задаётся явно через компрессор `xz --format=lzma`. Дополнительно проверяются фактический формат и целостность потока перед удалением оригиналов. В Windows LZMA создаётся штатным bsdtar и проверяется распаковкой и контрольными суммами.

## Тестирование

Автоматические тесты создают по 512 МиБ данных: четыре файла по 128 МиБ с разными датами модификации. Для расчёта используется ёмкость 640 МиБ, исходное заполнение составляет 80%. Подготовка и очистка окружения выполняются без ручного создания файлов и без root.

| Порог | Архивируется файлов | Остаток | Заполнение после |
|---|---:|---:|---:|
| 90% | 0 | 512 МиБ | 80% |
| 80% | 0 | 512 МиБ | 80% |
| 70% | 1 | 384 МиБ | 60% |
| 50% | 2 | 256 МиБ | 40% |
| 0% | 4 | 0 | 0% |

Отдельно проверяются LZMA, некорректный порог, нулевая ёмкость, backup внутри источника, неверный режим сжатия и существующая блокировка. В Bash дополнительно моделируется отказ архиватора. Ошибочные запуски используют папку размером 512 МиБ и проверяют сохранность её содержимого.

Проверки включают число и имена выбранных файлов, распаковку, SHA-256 архивированных и оставшихся данных, итоговый размер, пропуск ссылок на внешние папки и очистку блокировки. Дополнительные регрессионные проверки охватывают необычные имена и создание настоящего LZMA при некорректном неявном выборе компрессора.

Полученные результаты подтверждают корректность выбора файлов, восстановимость архивов и сохранность исходных данных в проверенных ошибочных сценариях. Локальные текстовые протоколы и сведения об их окружении находятся в `test-results/`.

## Ограничения и сложность

Папка должна оставаться неподвижной во время работы. Блокировка защищает от второго экземпляра архиватора, но не останавливает сторонние программы. Проверка и удаление не образуют атомарную транзакцию. При ошибке удаления опубликованный архив сохраняется, хотя часть оригиналов уже может быть удалена.

Сортировка k файлов требует O(k log k) времени и O(k) памяти. Архивирование и проверка линейны по объёму выбранных данных. В Windows необходимо дополнительное место для распакованной проверочной копии.

## Вывод

Реализовано архивирование наиболее старых файлов с контролем порога, проверкой содержимого перед удалением и обработкой ошибок. Подготовлены автоматические тесты, режимы gzip/LZMA и версия для Windows. Обе версии успешно прошли наборы проверок в указанных окружениях.
