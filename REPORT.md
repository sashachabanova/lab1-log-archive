## Цель

Написать Bash-скрипт для контроля размера папки и архивирования её самых старых файлов. Подготовить второй shell-скрипт, самостоятельно создающий тестовые данные и проверяющий результат. Реализовать дополнительные условия LZMA и Windows.

## Принятое определение заполнения

В условии есть неоднозначность: у обычного каталога нет собственной максимальной ёмкости. Принята формула:

`U = 100 × S / C`,

где S — сумма логических длин обычных файлов во всём дереве, C — ёмкость файловой системы либо явно указанная логическая квота. Каталоги и символические ссылки в S не входят.

По умолчанию C берётся из `df -Pk` в Linux и `DriveInfo.TotalSize` в Windows. Для тестов передаётся C = 640 МиБ. Это позволяет без root получить управляемое заполнение, не занимая 70% всего диска и не создавая отдельный раздел. Параметр квоты не устанавливает реальную дисковую квоту в ОС.

Сравнение выполняется до округления процентов:

`100 × S > X × C`.

При точном равенстве архивирование не выполняется: в задании сказано «больше». Две цифры после запятой нужны только для удобства вывода.

## Алгоритм

1. Проверить аргументы, зависимости, расположение backup и режим сжатия.
2. Создать блокировку `.lab1.lock`, уникальную временную рабочую папку.
3. Найти обычные файлы рекурсивно, не переходя по ссылкам.
4. Отсортировать по дате последней модификации от старых к новым.
5. Посчитать S и U. Если порог не превышен, закончить без архива.
6. Выбирать файлы с начала списка, пока расчётный остаток превышает порог.
7. Создать архив только выбранных файлов. Сохранить относительные пути.
8. Проверить архив против оригиналов. В Bash используется `tar --compare`; в Windows — распаковка во временную папку и сравнение SHA-256.
9. Переместить готовый архив из временной папки в backup под уникальным именем.
10. Удалить только выбранные оригиналы, вывести результат, очистить временные данные и блокировку.

## Почему выбрано правильное число файлов

Пусть файлы отсортированы по mtime: f1, f2, …, fk. После выбора первых n файлов остаётся

`R(n) = S − size(f1) − … − size(fn)`.

На каждом шаге проверяется `100 × R(n) > X × C`. Первый n, для которого неравенство перестаёт выполняться, даёт самый короткий префикс списка старых файлов. Префикс из n−1 файлов ещё не достигал порога. Это минимальное N **при обязательном выборе от самых старых к новым**, а не задача поиска произвольного набора файлов минимальной мощности.

Если несколько файлов имеют одинаковый mtime, их взаимный порядок не влияет на соблюдение условия «самые старые»; конкретный выбор среди них может различаться между платформами.

## Пример

Имеются четыре файла по 128 МиБ с разными mtime. Ёмкость 640 МиБ, S = 512 МиБ, U = 80%.

| Порог | Выбрано файлов | Остаток | Заполнение после |
|---|---:|---:|---:|
| 90% | 0 | 512 МиБ | 80% |
| 80% | 0 | 512 МиБ | 80% |
| 70% | 1 самый старый | 384 МиБ | 60% |
| 50% | 2 самых старых | 256 МиБ | 40% |
| 0% | 4 | 0 | 0% |

Удаление первого файла может опустить заполнение ниже порога сразу на 20 процентных пунктов. Это нормально: файл архивируется целиком.

## Проверки

Положительные сценарии: ниже порога, ровно порог, выбор одного старого файла, выбор двух старых файлов, LZMA и нулевой порог. Проверяются размер исходных данных, число архивов, формат, распаковка, число членов, контрольные суммы архивированных и оставшихся файлов, итоговый размер и очистка блокировки. Во время этих сценариев ссылка на внешнюю папку проверяет, что её данные не захватываются.

Ошибочные сценарии: некорректный порог, нулевая ёмкость, backup внутри источника, неверная переменная сжатия, уже существующая блокировка. В Bash дополнительно подставляется архиватор, завершающийся с кодом 42: проверяется сохранность оригиналов, отсутствие итогового архива и снятие своей блокировки.

Ошибочные сценарии могут использовать одну полугигабайтную папку последовательно: каждый запуск обязан сохранить её неизменной, это проверяется контрольными суммами. Во всех этих запусках размер входной папки остаётся 512 МиБ.

## Результат и ограничения

Реализованы основной сценарий и дополнительные условия со слайдов. Подробные фактические результаты находятся в `test-results/`. Windows-вариант запускается через `.bat`, но его алгоритм написан в `.ps1`; это явное архитектурное решение, а не чистый CMD.

Скрипт рассчитан на неподвижную папку логов. Если другие программы продолжают менять файлы, полной атомарности между проверкой архива и удалением нет. Архивирование и удаление не являются одной операцией файловой системы. Для учебной демонстрации генератор данных завершает запись до запуска архиватора.

Сложность сортировки O(k log k), где k — число файлов; память O(k). Создание и проверка архива линейны по объёму выбранных данных. Windows-версия дополнительно требует места под распакованную проверочную копию.
