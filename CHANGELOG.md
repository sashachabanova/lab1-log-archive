# Изменения

## 20 октября 2026 — явный выбор LZMA

Диагностика на присланном Ubuntu-снимке показала: GNU tar 1.35 с `--lzma` создаёт файл, который команда `file` определяет как `XZ compressed data, checksum CRC64`. Проверка `xz --format=lzma --test` корректно отвергает этот файл: расширение `.tar.lzma` не делает XZ потоком LZMA.

В `log_archive.sh` компрессор теперь задаётся явно через `--use-compress-program=xz --format=lzma`. Перед удалением оригиналов добавлена проверка настоящего формата LZMA. В тесте воспроизводится неправильный формат от команды `lzma`, а затем проверяется работа основного скрипта в том же окружении. Обновлены объяснения, протокол и контрольные суммы.

Для обновления нужны оба Bash-файла, а не только тестовый скрипт. Windows-реализация не менялась.

## 20 октября 2026 — исправление проверки SHA-256

На присланном снимке Ubuntu/WSL первый сценарий завершился сообщениями `no properly formatted checksum lines found` и `FAIL: Remaining bytes differ`. Сообщение возникало при чтении записи контрольной суммы файла с переводом строки в имени. Первые три файла прошли проверку; сам сценарий не запускал архивирование, поскольку 80% не превышали порог 90%.

Исправлен `test_log_archive.sh`:

- контрольная сумма вычисляется из stdin файла, без включения его имени в результат;
- сохраняются и сравниваются только 64 шестнадцатеричные цифры SHA-256;
- файл с переводом строки в имени по-прежнему участвует во всех положительных сценариях;
- добавлена быстрая проверка известных хешей и обнаружения изменения содержимого для необычных имён;
- полный набор из 12 сценариев прогнан повторно в локальном MSYS2.

Изменены описание тестов, README, протокол Bash и манифест контрольных сумм. Основной Bash-архиватор и Windows-версия не менялись. Отдельный успешный Linux/Ubuntu-прогон этим обновлением не заявляется: его нужно повторить на компьютере, с которого прислан снимок.
