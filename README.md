# Лабораторная работа №1: архивирование старых файлов

Комплект по требованиям со слайдов: два Bash-скрипта, автоматические тесты с папками по 512 МиБ, gzip, дополнительный LZMA-режим и Windows-версия с точками входа `.bat`.

**Обновление от 20 октября:** исправлены проверка контрольных сумм необычных имён и выбор формата LZMA. Вместо зависимости от `tar --lzma` основной скрипт явно использует `xz --format=lzma` и проверяет формат до удаления оригиналов. Если у вас старая распаковка, замените **оба** файла `log_archive.sh` и `test_log_archive.sh`; удобнее распаковать новый комплект целиком. Windows-версия не менялась.

## Что передать группе

Передавайте всю папку `lab1` или архив `lab1-ready.zip`. Для Windows нужны и `.bat`, и соседние `.ps1`: `.bat` запускает Windows PowerShell, в котором находится реализация. Bash для Windows-версии не требуется. Это решение использует штатные средства Windows, но **не является реализацией всей логики исключительно на языке CMD**. На слайде указан формат `.bat`, дополнительного запрета на PowerShell нет; если такой запрет был озвучен устно, его нужно учитывать.

## Что означает процент заполнения

Обычная папка не имеет собственной ёмкости. В этом решении:

`заполнение = сумма длин обычных файлов в папке и подпапках / ёмкость × 100%`.

По умолчанию ёмкость берётся у файловой системы/диска, где расположена папка. Четвёртым аргументом можно задать логическую ёмкость папки в МиБ. Это явно заданная квота для расчёта, а не созданный раздел и не ограничение ОС. Тесты используют 640 МиБ, поэтому 512 МиБ файлов дают ровно 80%.

Занятое место остальных папок диска не включается в числитель. Это **не** показатель общего заполнения диска `df Use%`. В слайдах нет однозначного определения ёмкости папки, поэтому формула является принятым и документированным допущением. Если преподаватель требует именно общий `df Use%`, это другая постановка: она зависит ещё и от посторонних файлов на диске.

Считаются логические длины файлов в байтах, а не число выделенных блоков. Ссылки, junction и каталоги не учитываются. Жёсткие ссылки считаются как отдельные файловые имена. Sparse-файл учитывается по логической длине. В тестах sparse-файлы и одни лишь объявления размера не используются: данные записываются блоками.

## Linux: запуск в учебной виртуальной машине

Окружение: Bash 4+, GNU findutils/coreutils, GNU tar, awk, gzip, xz-utils. На Debian/Ubuntu при отсутствии пакетов их установка выполняется один раз:

```bash
sudo apt-get update
sudo apt-get install bash coreutils findutils tar gawk gzip xz-utils
```

Сами скрипты и тесты запускаются обычным пользователем, без `sudo`, loop-устройств, монтирования и test-разделов. Перейдите в папку проекта:

```bash
bash log_archive.sh --help
bash test_log_archive.sh
```

Ожидаемый итог: `RESULT: 12 tests passed.` Тесты сами создают и удаляют своё окружение. Нужны примерно 2 ГиБ свободного места и несколько минут, скорость зависит от диска и процессора. Одновременно хранится один сценарий. В архивируемых данных много нулей, поэтому архивы небольшие; входные файлы при этом действительно записаны.

Общий формат:

```text
bash log_archive.sh LOG_DIR [THRESHOLD_PERCENT] [BACKUP_DIR] [CAPACITY_MIB]
```

Порог — целое число от 0 до 100 включительно; по умолчанию 70. Ёмкость в МиБ — положительное целое число до 999999999. Аргументы позиционные: чтобы указать ёмкость, укажите также порог и backup.

```bash
# Существующая папка логов, порог 70%, backup рядом, ёмкость файловой системы.
bash log_archive.sh "$HOME/my-logs"

# Явная квота 640 МиБ, отдельный каталог архивов.
bash log_archive.sh "$HOME/my-logs" 70 "$HOME/my-backup" 640

# LZMA применяется только к этому запуску.
LAB1_MAX_COMPRESSION=1 bash log_archive.sh "$HOME/my-logs" 70 "$HOME/my-backup" 640

# Просмотр и восстановление: подставьте настоящее имя архива.
tar -tf "$HOME/my-backup/archive-ИМЯ.tar.gz"
mkdir -p "$HOME/restore"
tar -xf "$HOME/my-backup/archive-ИМЯ.tar.gz" -C "$HOME/restore"
```

Оба вида архива распаковываются `tar -xf`; для LZMA в Linux нужен пакет xz-utils. Основной скрипт при превышении порога **удаляет именно успешно заархивированные оригиналы**. Для демонстрации используйте тестовую папку. Папка backup должна находиться вне папки логов.

## Windows: запуск

Требуются Windows PowerShell 5.1 и `tar.exe` с gzip/LZMA из комплекта Windows. В этой среде использован штатный bsdtar/libarchive. Дополнительные модули PowerShell не нужны. Откройте **CMD** в папке `lab1`:

```bat
windows\test_log_archive.bat
windows\log_archive.bat --help
windows\log_archive.bat "C:\demo\log" 70 "C:\demo\backup" 640
set LAB1_MAX_COMPRESSION=1
windows\log_archive.bat "C:\demo\log" 70 "C:\demo\backup" 640
set LAB1_MAX_COMPRESSION=
```

Ожидаемый итог тестов: `RESULT: 11 tests passed.` Запуск из PowerShell:

```powershell
.\windows\test_log_archive.bat
.\windows\log_archive.bat 'C:\demo\log' 70 'C:\demo\backup' 640
$env:LAB1_MAX_COMPRESSION = '1'
.\windows\log_archive.bat 'C:\demo\log' 70 'C:\demo\backup' 640
Remove-Item Env:\LAB1_MAX_COMPRESSION
```

Тесты Windows также записывают 512 МиБ на сценарий, проверяют распаковку, SHA-256 и пропуск junction. Запускайте Linux- и Windows-тесты последовательно, если свободного места мало.

## Границы применения

- На время работы запись в папку логов должна быть остановлена. Проверка архива ловит многие изменения, но не делает внешних писателей участниками транзакции.
- `.lab1.lock` защищает от второго экземпляра этого скрипта на той же папке. После аварийного завершения питания или `kill -9` блокировка может остаться. Удалять её вручную следует только после проверки, что другой запуск действительно завершён.
- Папка содержит обычные учебные данные: защита от злонамеренной подмены дерева каталогов во время запуска не реализована.
- При ошибке создания/проверки архива удаление не начинается. После публикации архива ошибка удаления может оставить часть оригиналов; архив при этом сохраняется.
- Пустые подпапки сохраняются. Если порог 0, для освобождения места могут быть выбраны все файлы.
- Поддерживаемая Unix-среда — GNU/Linux. macOS/BSD-утилиты с другими опциями отдельно не поддерживаются.

## Что осталось сделать перед сдачей

1. Прогнать `bash test_log_archive.sh` в вашей учебной Linux-VM. Фотографии требуют установленную виртуальную машину; набор файлов её не заменяет.
2. Прочитать `CODE_EXPLAINED.md`, `LINE_BY_LINE.md` и отрепетировать `DEFENSE.md`.
3. Добавить имена участников в `REPORT.md`.
4. Создать доступный преподавателю репозиторий GitHub/GitLab и загрузить **всю** папку. Не загружать тестовые полугигабайтные файлы и созданные архивы. Скрипты тестов сами их создадут.
5. По регламенту со слайда заранее отправить преподавателю ссылку на репозиторий. Публикация репозитория и отправка письма этим комплектом не выполнялись.

Фактические проверки и ограничения окружения перечислены в `test-results/README.md`. Оценку определяет преподаватель, в том числе по объяснению кода каждым участником.
