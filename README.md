## Описание

Проект автоматизирует архивирование старых файлов при превышении порога заполнения папки. Реализованы Bash-версия для GNU/Linux, Windows-версия с запуском через `.bat` и автоматические тесты. Поддерживаются gzip и LZMA.

Скрипт получает путь к папке, вычисляет заполнение и сравнивает его с порогом. При превышении порога файлы сортируются по времени последнего изменения, после чего выбираются самые старые. Выбранные файлы архивируются и проверяются. Только после успешной проверки удаляются их оригиналы.

## Расчёт заполнения

`U = 100 × S / C`, где S — сумма логических размеров обычных файлов в папке и подпапках, C — расчётная ёмкость.

По умолчанию используется общая ёмкость файловой системы или диска. Четвёртым аргументом можно задать логическую ёмкость в МиБ. Она используется в формуле и не устанавливает дисковую квоту средствами ОС. Другие папки диска в S не включаются; это показатель заполнения выбранного каталога относительно C, а не общий `df Use%`.

Порог по умолчанию — 70%. При точном равенстве порогу архивирование не выполняется. Символические ссылки и Windows junction при обходе пропускаются.

## Запуск в GNU/Linux

Зависимости: Bash 4+, GNU coreutils/findutils, GNU tar, awk, gzip и xz-utils.

Формат запуска:

```text
bash log_archive.sh LOG_DIR [THRESHOLD_PERCENT] [BACKUP_DIR] [CAPACITY_MIB]
```

Пример для существующей папки логов с порогом 70% и расчётной ёмкостью 640 МиБ:

```bash
bash log_archive.sh "$HOME/my-logs" 70 "$HOME/my-backup" 640
```

Режим LZMA:

```bash
LAB1_MAX_COMPRESSION=1 bash log_archive.sh "$HOME/my-logs" 70 "$HOME/my-backup" 640
```

В Bash-версии LZMA задаётся явно через `xz --format=lzma`; формат проверяется до удаления оригиналов. Без переменной используется gzip. Папка backup должна находиться вне папки логов. Без дополнительных аргументов порог равен 70%, backup создаётся рядом с источником, а ёмкость берётся у файловой системы.

Запуск автоматических тестов:

```bash
bash test_log_archive.sh
```

Ожидаемый результат: `RESULT: 12 tests passed.`

## Запуск в Windows

Зависимости: Windows PowerShell 5.1 и штатный `tar.exe` с поддержкой gzip/LZMA. Файлы `.bat` запускают соседние `.ps1`, поэтому они используются совместно. Реализация Windows не требует Bash.

Команды для CMD:

```bat
windows\log_archive.bat "C:\demo\log" 70 "C:\demo\backup" 640
windows\test_log_archive.bat
```

Режим LZMA:

```bat
set LAB1_MAX_COMPRESSION=1
windows\log_archive.bat "C:\demo\log" 70 "C:\demo\backup" 640
set LAB1_MAX_COMPRESSION=
```

Ожидаемый результат тестов: `RESULT: 11 tests passed.`

## Тестирование

При выполнении работы получены следующие результаты:

- Ubuntu в WSL — успешно пройдены 12 тестов.
- Windows — успешно пройдены 11 тестов.

Каждый основной сценарий использует папку с 512 МиБ данных. Тесты самостоятельно создают файлы, задают время модификации, запускают архивирование и проверяют результат. Ошибочные сценарии повторно используют неизменённую папку того же размера.

Проверяются границы порога, выбор одного и нескольких старых файлов, нулевой порог, gzip, LZMA, обработка некорректных аргументов и блокировки. Содержимое распакованных и оставшихся файлов сравнивается по SHA-256. В Bash дополнительно проверяется отказ архиватора и работа при ошибочном неявном выборе формата сжатия.

Для тестов рекомендуется около 2 ГиБ свободного места. Сгенерированные данные и временные папки очищаются автоматически. Происхождение текстовых протоколов описано в `test-results/README.md`.

## Ограничения

- На время архивирования внешняя запись в папку должна быть остановлена.
- `.lab1.lock` предотвращает одновременную работу нескольких экземпляров архиватора с одним источником.
- При ошибке создания или проверки архива удаление оригиналов не начинается. При ошибке последующего удаления проверенный архив сохраняется.
- После аварийного завершения может остаться блокировка. Перед её ручным удалением необходимо убедиться, что другой экземпляр не работает.
- Используются логические длины файлов, а не число выделенных дисковых блоков. Жёсткие ссылки учитываются по отдельным файловым именам.
- Пустые подпапки сохраняются. При пороге 0 могут быть выбраны все файлы.
- Bash-версия использует GNU-утилиты; совместимость с macOS/BSD отдельно не проверялась.
