# Демонстрация работы и технические вопросы

## Подготовка примера

Демонстрация использует отдельную временную папку и четыре файла по 128 МиБ с разными датами модификации. Команды выполняются в GNU/Linux из папки проекта:

```bash
DEMO=$(mktemp -d "$HOME/lab1-demo.XXXXXXXX")
mkdir -p "$DEMO/log" "$DEMO/backup"
for i in 1 2 3 4; do
    dd if=/dev/zero of="$DEMO/log/$i.log" bs=1M count=128 status=none
    touch -t "2020010${i}0000.00" "$DEMO/log/$i.log"
done
printf 'Demo directory: %s\n' "$DEMO"
```

Общий размер составляет 512 МиБ. При расчётной ёмкости 640 МиБ заполнение равно 80%. Переменная DEMO используется в том же терминале.

## Архивирование в gzip

```bash
ls -lh "$DEMO/log"
bash log_archive.sh "$DEMO/log" 70 "$DEMO/backup" 640
ls -lh "$DEMO/log" "$DEMO/backup"
tar -tf "$DEMO"/backup/*.tar.gz
```

Ожидается выбор файла `1.log`, поскольку его mtime самый ранний. После проверки архива его оригинал удаляется, остаётся 384 МиБ, или 60%. В архиве находится только `1.log`.

Повторный запуск с порогом 70% не создаёт новый архив, поскольку превышения уже нет.

## Архивирование в LZMA

После предыдущего примера:

```bash
LAB1_MAX_COMPRESSION=1 bash log_archive.sh "$DEMO/log" 50 "$DEMO/backup" 640
ls -lh "$DEMO/backup"
```

Из оставшихся файлов выбирается `2.log`. Заполнение снижается с 60% до 40%; появляется отдельный `.tar.lzma`. Настоящий формат LZMA задаётся явно и проверяется до удаления оригинала.

## Проверка тестами

GNU/Linux:

```bash
bash test_log_archive.sh
```

Windows CMD:

```bat
windows\test_log_archive.bat
```

Ожидаются 12 и 11 пройденных тестов соответственно. Тесты генерируют данные автоматически; положительные сценарии включают распаковку и сравнение содержимого по SHA-256.

## Технические вопросы

**Как определяется заполнение?** Сумма логических длин обычных файлов делится на расчётную ёмкость и умножается на 100. По умолчанию ёмкость берётся у файловой системы; для тестов передаётся 640 МиБ. Данные остальных папок не входят в числитель.

**Почему при 80% и пороге 80% архив не создаётся?** Условие запуска — строгое превышение. Сравнение выполняется без округления процентов.

**Что считается возрастом файла?** Время последней модификации mtime. Время создания и время последнего чтения не используются.

**Почему число выбранных файлов минимально?** Выбор останавливается на первом префиксе списка по возрасту, достаточном для достижения порога. Произвольные комбинации файлов не перебираются.

**Зачем NUL и кавычки?** NUL однозначно разделяет Unix-имена, включая имена с переводами строк. Кавычки сохраняют каждый путь одним аргументом. `--` отделяет имена от опций команд.

**Почему Bash, а не sh?** Используются массивы, `[[ ... ]]`, `read -d` и другие расширения Bash.

**Что делает tar, а что — gzip/LZMA?** Tar объединяет файлы и метаданные в поток. Компрессор сжимает этот поток. Расширение само по себе не определяет фактический формат.

**Почему формат LZMA задаётся явно?** При тестировании встречалось создание XZ через неявный компрессор GNU tar. Команда `xz --format=lzma` исключает зависимость от такого выбора; формат дополнительно проверяется.

**Когда удаляются оригиналы?** После создания, проверки и публикации архива в backup. При ошибке создания или проверки удаление не начинается.

**Что при ошибке удаления?** Опубликованный архив сохраняется. Часть оригиналов может остаться, поскольку удаление не является атомарной транзакцией.

**Как работает блокировка?** Создание нового каталога `.lab1.lock` допускает только один экземпляр для источника. Очистка снимает свою блокировку. Аварийное отключение питания или SIGKILL могут оставить её на диске.

**Можно ли продолжать запись в логи?** Заявленный режим предполагает неподвижную папку. Блокировка не останавливает внешние программы; полной защиты от изменения файлов между проверкой и удалением нет.

**Почему Windows-версия использует PowerShell?** Файлы `.bat` обеспечивают запуск, а `.ps1` реализуют вычисления, работу с датами, буквальными путями и SHA-256 средствами Windows. Bash для этого варианта не требуется.

**Что подтверждают результаты?** Успешное прохождение 12 тестов в Ubuntu/WSL и 11 тестов в Windows, включая выбор файлов и сохранность содержимого в проверенных сценариях. Это не доказательство поведения при любых возможных отказах ОС.
