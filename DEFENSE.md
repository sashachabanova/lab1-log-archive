# Подготовка к защите

На слайде указано: до 1 минуты демонстрации, затем 2 минуты комментариев к коду, затем вопросы. Каждому участнику нужно понимать решение целиком.

## Перед занятием

1. Скопировать комплект в учебную Linux-VM. Наличие Git Bash/MSYS2 на Windows само по себе не заменяет требование установить виртуальную машину из переписки.
2. Выполнить полный `bash test_log_archive.sh` заранее. Должно быть 12 PASS и итог `RESULT: 12 tests passed.`
3. Выполнить Windows-тесты через `.bat`: ожидается 11 PASS.
4. Загрузить исходники в GitHub/GitLab, проверить доступ преподавателя. Нужен настоящий URL своего репозитория; в комплекте он не выдуман.
5. Добавить имена в REPORT.md. Не прикладывать сгенерированные данные на гигабайты.
6. Согласовать понимание процента: папка не имеет собственной ёмкости, наше определение описано в отчёте.

## Демонстрация на одну минуту

Полный набор тестов не нужно пытаться уместить в минуту. Его протокол можно открыть заранее. Для живой демонстрации подготовьте безопасные данные следующими командами **до начала отсчёта** в GNU/Linux:

```bash
DEMO=$(mktemp -d "$HOME/lab1-demo.XXXXXXXX")
mkdir -p "$DEMO/log" "$DEMO/backup"
for i in 1 2 3 4; do
    dd if=/dev/zero of="$DEMO/log/$i.log" bs=1M count=128 status=none
    touch -t "2020010${i}0000.00" "$DEMO/log/$i.log"
done
printf 'Demo directory: %s\n' "$DEMO"
```

Переменная `DEMO` действует в этом же терминале. Подготовка даёт четыре файла по 128 МиБ, всего 512 МиБ. На защите:

```bash
ls -lh "$DEMO/log"
bash log_archive.sh "$DEMO/log" 70 "$DEMO/backup" 640
ls -lh "$DEMO/log" "$DEMO/backup"
tar -tf "$DEMO"/backup/*.tar.gz
```

Что сказать: «Ёмкость для демонстрации 640 МиБ, файлы занимают 512 МиБ, то есть 80%. Порог — 70%. Скрипт выбирает самый старый файл 1.log, архивирует и проверяет его, после чего удаляет оригинал. Остались 384 МиБ — 60%. В архиве только 1.log».

Повторный такой же запуск ничего не архивирует: 60% уже меньше 70%. Это можно показать одной дополнительной командой.

Для LZMA нужна исходная папка с превышенным порогом. После первого примера можно использовать более низкий порог:

```bash
LAB1_MAX_COMPRESSION=1 bash log_archive.sh "$DEMO/log" 50 "$DEMO/backup" 640
ls -lh "$DEMO/backup"
```

Теперь остаток меняется с 60% до 40%, появляется отдельный `.tar.lzma` с файлом 2.log. На медленной VM создание архива может занять заметное время; полный дополнительный тест уже есть в протоколе.

Демонстрационная папка сохраняется для просмотра. После занятия удалите именно папку, которую напечатал `printf`, если её содержимое больше не нужно.

## Комментарий к коду на две минуты

«Основной скрипт принимает путь к папке, порог, путь до backup и необязательную квоту. По умолчанию порог 70%, ёмкость — размер файловой системы. Папка сама по себе не имеет ёмкости, поэтому формула явно определена в отчёте.

Сначала проверяются аргументы и создаётся блокировка. Затем find собирает mtime, размер и относительное имя каждого обычного файла. Символические ссылки не обходятся. Записи заканчиваются NUL, поэтому имена с пробелами и переводами строк обрабатываются правильно. sort сортирует по mtime от старых к новым.

Суммируем размеры и сравниваем целые произведения, без округления процентов. При превышении порога выбираем файлы с начала списка и вычитаем их размеры, пока остаток не станет допустимым. Получается минимальный префикс самых старых файлов.

Tar создаёт архив по подготовленному списку, затем tar --compare проверяет его относительно ещё существующих оригиналов. После этого готовый архив перемещается в backup, и только выбранные оригиналы удаляются. Trap очищает временные файлы и блокировку.

Второй скрипт сам создаёт полгигабайта данных, назначает даты и проверяет ожидаемые имена и SHA-256 после распаковки. Есть границы порога, один и несколько файлов, LZMA и ошибки. Windows-версия запускается через bat, использует PowerShell и штатный tar; архив дополнительно распаковывается для проверки хешей».

## Вопросы, которые нужно уметь объяснить

**Почему не `du / df Use%`?** В нашей постановке считается доля ёмкости, занятая файлами заданной папки. `df Use%` относится ко всем данным файловой системы, а `du` по умолчанию считает выделенные блоки. Это другие величины. Определение и ограничение явно записаны.

**Почему квота не подмена теста?** Передаются реальные 512 МиБ файлов. Квота — параметр знаменателя в формуле, а не поддельный ответ системной команды. Это позволяет проверить алгоритм без заполнения всего диска и без root. Если требовался исключительно отдельный раздел, нужен другой тестовый стенд, а такого требования на слайде нет.

**Почему `>` вместо `>=`?** В условии «больше X%». Точное равенство не запускает архивацию, что проверяет отдельный тест.

**Почему после удаления получается 60%, а не ровно 70%?** Файлы нельзя делить для этого задания. Один файл целиком уменьшает размер с 512 до 384 МиБ.

**Что значит «старый»?** Минимальное время последней модификации mtime. Это не время создания и не atime.

**Что если mtime одинаковый?** Оба файла одинаково старые. Конкретный порядок среди них допустим, межплатформенное совпадение выбранных имён при таких связках не обещается. В тестах времена различаются.

**Почему N минимально?** Перед выбором N-го файла условие ещё нарушалось. После выбора выполняется. Но минимальность относится к префиксу списка, упорядоченного по возрасту; не к произвольной комбинации файлов.

**Что делает `--`?** Заканчивает опции команды; следующее имя с дефисом — имя, а не ключ.

**Зачем NUL?** Перевод строки может быть частью Unix-имени, NUL — не может. Список строк ненадёжен.

**Почему не `ls | sort`?** `ls` — форматированный вывод для человека, не безопасный формат перечисления произвольных имён с метаданными.

**Почему основной `while` без конвейера?** Переменные и массивы должны изменяться в текущем процессе. Перенаправление из файла обеспечивает это.

**Как работают `${record#* }` и `${rest%% *}`?** Первая конструкция снимает кратчайший префикс до первого пробела. Вторая снимает самый длинный хвост, начинающийся пробелом, оставляя первый столбец. Так отделяются два служебных поля, а всё оставшееся — имя.

**Почему Bash, а не `sh`?** Используются Bash-массивы, `[[ ... ]]`, `read -d` и другие расширения. Запускать нужно `bash`, а не `sh`.

**Чем tar отличается от gzip?** Tar объединяет файлы и метаданные в один поток; gzip сжимает этот поток. LZMA — альтернативный алгоритм сжатия. Расширение не меняет содержимое само по себе.

**Что включает `LAB1_MAX_COMPRESSION=1`?** GNU tar использует явно заданный компрессор `xz --format=lzma`; архив становится `.tar.lzma`. Формат дополнительно проверяется до удаления оригиналов. На одном из Ubuntu-прогонов `tar --lzma` создавал XZ, поэтому на этот неявный выбор больше не полагаемся. Условие со слайда требует алгоритм LZMA, а не доказательство абсолютного лучшего размера для всех входов.

**Почему не удалять файлы до проверки?** Ошибка записи архива иначе могла бы уничтожить единственную копию. Удаление идёт только после успешного создания, проверки и публикации.

**Что при нехватке места?** Tar возвращает ошибку, удаление не начинается; временные данные очищаются. В Windows нужно место ещё и для распаковки проверочной копии.

**Что при ошибке удаления второго файла?** Архив сохраняется. Часть предыдущих оригиналов могла уже удалиться. Это не атомарная транзакция, но в архиве находятся все выбранные данные.

**Можно ли писать в логи во время запуска?** В заявленном режиме — нет. Проверка обнаруживает многие изменения, но между последней проверкой и удалением остаётся временное окно. Блокировка защищает от другого экземпляра архиватора, а не от любой программы.

**Кто снимает чужую блокировку?** Скрипт её не снимает. Отказ происходит до регистрации своей очистки в Bash; в Windows проверяется `$lockOwned`.

**Что делает trap?** Запускает cleanup на EXIT. INT/TERM приводят к выходу, затем очистке. SIGKILL обработать нельзя.

**Чем отличаются логическая длина и место на диске?** У sparse-файла большая длина может занимать мало блоков; несколько жёстких ссылок могут указывать на одни данные. У нас модель по длинам имён файлов, а не подсчёт уникальных выделенных блоков.

**Почему Windows написан через PowerShell?** .bat — публичная точка запуска; PowerShell даёт 64-битные числа, безопасную работу с буквальными путями, даты и SHA-256. CMD неудобен для такой логики. В комплекте это явно указано; чистый язык CMD не заявлен.

**Что доказывают тесты?** На конкретных сценариях проверяются реальные данные, выбор старых файлов и восстановимость архива, а не только код завершения. Тесты не доказывают корректность для всех возможных отказов ОС.

**Где фактический Linux-прогон?** Приложенный Bash-протокол получен в MSYS2 с GNU-утилитами на Windows. Linux-VM отдельно ещё должен проверить участник перед сдачей. Называть MSYS2 Linux-виртуалкой нельзя.

## Распределение подготовки в группе

Один участник может показать ввод и формулу, второй — выбор файлов и tar, третий — тесты и Windows. При этом каждому нужно уметь объяснить любой блок: на фотографии это явно включено в регламент.
